01 / The philosophy

Start with the light.
Not a prediction.

A natural starting point should be a starting point—not an effect you have to undo.

01

Let the camera be a camera.

The default Natural profile starts with the JPEG exposed by your device’s Camera2 pipeline. At 1×, with no edits enabled, it preserves the original JPEG pixel data and adds capture metadata.

No mandatory film grade. No mandatory enlargement.
02

No AI enhancement added.

MobileFilmLab adds no generative image model, neural photo enhancement or cloud processing. Optional colour, sharpening, grain and fusion use conventional, non-ML algorithms.

What this does—and doesn’t—mean
03

Your photos stay yours.

Preview, capture, looks and recipe processing happen on-device. No advertising, analytics or photo uploads. The app contacts GitHub only when you choose to check for an update.

Read the privacy notice

Hardware-first isn’t a firmware bypass. JPEG still passes through the device ISP. Real sensor RAW/DNG is now available where Camera2 advertises it, without app-added colour, grain or crop. Even RAW can include hardware/firmware corrections; proprietary manufacturer processing remains outside the no-app-added-AI guarantee.

05 / A few honest answers

Before your
first frame.

No hidden magic.
No promises the hardware can’t keep.

Does the app use AI to process my photos?

MobileFilmLab adds no generative image model, ML enhancement or cloud photo processing. Its optional editing and fusion are conventional algorithms.

Your device’s camera/ISP still processes images, and optional manufacturer extensions may use proprietary techniques. We can’t promise that every firmware path is AI-free.

Can I capture real RAW files?

Yes, on camera routes that advertise usable RAW_SENSOR support. Choose RAW (DNG) only, RAW + JPEG, or JPEG only from the format badge or Settings. RAW-only requests no still JPEG; paired mode uses one timestamp-matched request.

DNG is written from the sensor image through Android DngCreator—not converted from a JPEG. No app recipe, grain, RGB correction, digital crop or interpolation is applied. RAW modes use standard Camera2, native 1× and advertised normal-pixel-mode sizes up to 55MP; OEM modes, fusion and ZSL are JPEG-only.

Firmware can reject advertised combinations. Real DNG validity and rendering still need handset testing in a RAW-capable editor. Hardware corrections can already be present in exposed RAW.

How do the Pro sliders work?

Tap a parameter tab to open its editor without changing the value. EV, ISO, shutter and white balance use sliders; Auto/metered is an explicit switch, and supported autofocus modes are direct choices.

EV needs both ISO and shutter set to Auto. If just one exposure axis is manual, the other uses a metered-and-held value—not true ISO/shutter-priority auto. Shutter is bounded by sensor/frame limits and 30 seconds; WB Kelvin is approximate. Unsupported controls show a reason.

Settings also has higher-contrast text, larger labels and a scrolling body with a persistent Done action. Actual handset display and manual-control behaviour still need testing.

How do I keep the most natural starting point?

Use the default Natural baseline, standard Camera2 processing, native output and 1× framing, with grain off and lens gains unchanged. In that unedited path, the exposed JPEG pixel data is preserved and capture/recipe metadata is added.

Choosing a look, crop, grain or calibration edit changes the result. Those creative choices stay in your hands.

How does the app find my lenses?

Camera2 provides public camera IDs, physical links behind logical cameras, focal lengths, sensor dimensions and stream capabilities. The selector now shows all exposed photo-capable rear routes instead of four fixed slots, and selects each by its exact ID.

Labels use approximate detected equivalent focal lengths, physical millimetres marked with an asterisk when necessary, or an ID if metadata is missing. Logical Auto routes are not additional physical lenses. Firmware-hidden cameras remain inaccessible.

Oppo Find X9 Ultra remains the primary target. Please send a device report to help expand compatibility.

Why is the screenshot scene AI-generated?

The screenshots render the app’s actual Android/Compose UI without a connected handset. The landscape and camera/RAW capability state are illustrative. They demonstrate the controls, not a captured photo, valid sensor DNG or device compatibility.

The project was also developed substantially with AI assistance. That is separate from the app’s photo-processing design. Read the development disclosure.

Is this a stable, universally tested camera app?

No. The current version is v0.2.0-beta.3, published as the latest regular GitHub Release by owner request. That classification does not turn it into a newly built stable version or certify every device and feature.

Keep another camera available for important photos and read the known limitations.
